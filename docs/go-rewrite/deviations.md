# Отличия Go-агента от TypeScript

Осознанные отличия поведения, внесённые при переносе (решения владельца — architecture §6:
переносим один в один, явные ошибки и дыры безопасности чиним и отмечаем). Видимые оркестратору
смены поведения сюда не вносятся без владельца.

| Где | Было в TS | В Go | Почему |
|---|---|---|---|
| `runner` (все внешние команды) | `/bin/sh -c` со строкой, без таймаута, maxBuffer 1 МиБ с убийством | argv без shell; таймаут обязателен (вызов без него отклоняется); по таймауту SIGTERM всей группе процессов, через 5 с SIGKILL; вывод обрезается на 8 МиБ без убийства | §6 п.4, A R-1, R-18; текст ошибки `Command failed: <cmd>\n<stderr>` сохранён байт в байт. `sh -c` остаётся только у настраиваемых команд (`RELOAD_COMMAND` и т. п.) через `Cmd.Shell` |
| `runner`: окружение детей | дети наследовали всё, включая `EGRESS_CONTROL_SECRET` | секрет из окружения детей убирается (`runner.ChildEnv`) | A R-9; ни одна внешняя команда секрет не читает |
| `runner`: нет файла | `spawn <file> ENOENT` | то же; но не-ELF файл даёт `exec format error`, а не fallback через `/bin/sh` (C §0.5) | исход тот же — отказ |
| `fsx` (запись файлов) | `writeFile` на месте, без fsync | temp в том же каталоге + fsync + rename + fsync каталога; права ставятся chmod явно; без явного режима — режим и владелец существующего файла сохраняются; симлинк — пишется цель | §6 п.3 |
| `config`: `LOG_LEVEL` | уровня нет, всегда info | необязательная 34-я переменная `LOG_LEVEL` (debug/info/warn/error, по умолчанию info), вне схемы 33 | бриф группы A: уровень из конфига |
| `config`: разбор `.env` | dotenv снимает кавычки регуляркой с обратной ссылкой | первая и последняя буквы сравниваются напрямую (в RE2 нет обратных ссылок) | расходится только на экзотике (многострочное значение со строками, начинающимися с кавычки) |
| keepalive сервера | grpc-js пинговал каждые 10 с независимо от активности и не ограничивал частоту пингов клиента | grpc-go пингует только простаивающее соединение (не реже 1 с — его зажим); `MinTime` 1 с, `PermitWithoutStream` | смысл тот же: мёртвый пир снимается через Time+Timeout; оркестратор (10 с) GOAWAY не получает — доказано тестом |
| `0.0.0.0` | IPv4 | явно `tcp4` для IPv4-адреса (Go по `tcp` слушал бы и IPv6) | паритет |
| неверный PEM | ошибка на `bindAsync` | ошибка при загрузке сертификатов (`failed to load`) | исход тот же — выход 1 |
| `GetAgentInfo`: хеш | proto читался из cwd при старте; нет файла — пустой хеш | хеш считается из дескриптора, вшитого в бинарник | A R-15 |
| версия | `git describe` в cwd → `package.json` → `1.0.0` | сначала версия из `-ldflags`, потом та же цепочка | бинарник без `.git` рядом |
| `SelfUpdate` | git reset + npm ci + build + restart, без замка и таймаутов | бинарник релиза, SHA-256, проверка `--version`, атомарная подмена, `.prev`; повтор во время работы — `success:true` «already in progress», второе не запускается | §3 (решение владельца), A R-3, R-4, R-5; см. `update.md` |
| `GetManagedCertificate` | cert и key читались параллельно — при двух сбоях ошибка «кто первый» | сначала cert, потом key | детерминизм; текст ошибки в форме Node (`ENOENT: no such file or directory, open '<путь>'`) сохранён |
| остановка | SIGTERM — немедленная смерть | `GracefulStop` до 3 с, затем `Stop` | A §1.4 допускает |
| фоновые циклы | `setInterval`, тики накладываются | `lifecycle.Loop`: следующий тик — после окончания текущего | architecture §2 |
| загрузки (группа C): приём | `/tmp/<имя>_<ms>_<hex>.tmp`, запись без учёта backpressure, без предела размера и fsync; ошибка записи роняла агент; отмена клиентом удаляла temp из-под идущего применения | бинарь принимается рядом с целью (`.<имя>.upload-*`, та же ФС — подмена простым rename, setcap кандидата переживает его, дымовой тест не упирается в `noexec` на `/tmp`); набор правил и исходник модуля — во временный каталог ОС; запись синхронная, fsync; предел 256 МиБ на бинарь, 32 МиБ на набор правил, 64 МиБ на исходник модуля (ответ `Failed to upload binary: upload exceeds the size limit of N bytes`); ошибка ФС — ответ `success:false`, а не падение; temp удаляется до ответа на всех путях | C §0.3, риски 5, 6, 9, 17; architecture §6 п.9 |
| загрузки: применение | обработчик `end` продолжался после отмены, но temp мог исчезнуть под ним; замков нет — две загрузки одной цели менялись местами и дважды перезапускали службу | после полуприёма (half-close) применение идёт под `context.WithoutCancel` — отключение клиента не обрывает подмену, перезапуск или сборку DKMS, temp принадлежит приёмнику до конца применения; замок на цель (AWG tools/quick/go — общий, наборы правил — общий) | C §12 п.34, риски 7, 8 |
| загрузки: откат | прежний бинарь не сохранялся, отката нет | заменённый файл остаётся `<цель>.prev`; если новый бинарь не поднялся — перезапуск упал или (sing-box, Caddy, mihomo) юнит, бывший активным до подмены, через 3 с не `active` — `.prev` возвращается на место, служба перезапускается на нём, ответ `success:false` с причиной. Без `.prev` (первая установка) — как в TS: sing-box и mihomo отвечают успехом, Caddy — ошибкой перезапуска | C риск 4, 13; бриф группы C. Видимо оркестратору только там, где узел иначе остался бы без службы |
| загрузки: проверка до подмены | дымовой тест только у sing-box (`version`), mihomo (`-v`), awg-quick (шебанг + `bash -n`) | дополнительно: заголовок ELF и архитектура узла у каждого готового бинаря (sing-box, awg, amneziawg-go, Caddy, mihomo, olcrtc-agent-srv); `--version` у awg и amneziawg-go (тот же вызов, что в телеметрии); у Caddy — `version` и `validate --config <Caddyfile>` кандидатом с `cloudflare.env` в окружении, отказ — `Бинарь Caddy <v> отвергнут: …` по образцу sing-box | C риски 2, 3 |
| `UploadCaddyBinary`: drop-in | `ExecStart=<bin> run --environ --config …` | без `--environ`: флаг печатал всё окружение Caddy, включая `CF_API_TOKEN` из `cloudflare.env`, в журнал. Первый же upload Go-агентом перепишет drop-in (daemon-reload + тот же перезапуск) | C риск 3 |
| `UpgradeSingbox` | curl с `--` перед `-o` — метод всегда падал (`Failed to upgrade sing-box binary: Command failed: curl …`), ничего не меняя | проверки секрета и URL с теми же текстами, затем честный отказ `Failed to upgrade sing-box binary: UpgradeSingbox is not supported by this agent …; deliver the binary with UploadSingboxBinary instead.`; ничего не скачивается | architecture §6 п.6 (решение владельца), C §2 |
| `UploadOlcrtcAgentSrvBinary`: список экземпляров | `systemctl list-units … \| awk '{print $1}'` | без shell; первое поле строки, значок состояния `●`/`*` пропускается, а не принимается за имя юнита | C §8, §6 п.4 |
| `UploadMeshAwgKernelSource` | `lsmod \| grep -w amneziawg`, `linux-headers-$(uname -r)`, `tar -xzf "<путь>"` через shell; `dkms status -m … -v …` без таймаута | без shell: `lsmod` + поиск слова в Go (текст сбоя прежний: `Command failed: lsmod \| grep -w amneziawg\n`), релиз ядра агент берёт сам (в тексте команды — значение, а не `$(uname -r)`), argv без кавычек; таймаут `dkms status` 30 с; остальные таймауты как в TS | §6 п.4, C §9 |
