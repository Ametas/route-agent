# Отличия Go-агента от TypeScript

Осознанные отличия поведения, внесённые при переносе (решения владельца — architecture §6:
переносим один в один, явные ошибки и дыры безопасности чиним и отмечаем). Видимые оркестратору
смены поведения сюда не вносятся без владельца.

| Где | Было в TS | В Go | Почему |
|---|---|---|---|
| `runner` (все внешние команды) | `/bin/sh -c` со строкой, без таймаута, maxBuffer 1 МиБ с убийством | argv без shell; таймаут обязателен (вызов без него отклоняется); по таймауту SIGTERM всей группе процессов, через 5 с SIGKILL; вывод обрезается на 8 МиБ без убийства | §6 п.4, A R-1, R-18; текст ошибки `Command failed: <cmd>\n<stderr>` сохранён байт в байт. `sh -c` остаётся только у настраиваемых команд (`RELOAD_COMMAND` и т. п.) через `Cmd.Shell` |
| `runner`: окружение детей | дети наследовали всё, включая `EGRESS_CONTROL_SECRET` | секрет из окружения детей убирается (`runner.ChildEnv`) | A R-9; ни одна внешняя команда секрет не читает |
| `runner`: нет файла | `spawn <file> ENOENT` | то же; но не-ELF файл даёт `exec format error`, а не fallback через `/bin/sh` (C §0.5) | исход тот же — отказ |
| `fsx` (запись файлов) | `writeFile` на месте, без fsync | temp в том же каталоге + fsync + rename + fsync каталога; права ставятся chmod явно; без явного режима — режим и владелец существующего файла сохраняются; симлинк — пишется цель | §6 п.3 |
| `config`: `LOG_LEVEL` | уровня нет, всегда info | необязательная 34-я переменная `LOG_LEVEL` (debug/info/warn/error, по умолчанию info), вне схемы 33 | бриф группы A: уровень из конфига |
| `config`: разбор `.env` | dotenv снимает кавычки регуляркой с обратной ссылкой | первая и последняя буквы сравниваются напрямую (в RE2 нет обратных ссылок) | расходится только на экзотике (многострочное значение со строками, начинающимися с кавычки) |
| keepalive сервера | grpc-js пинговал каждые 10 с независимо от активности и не ограничивал частоту пингов клиента | grpc-go пингует только простаивающее соединение (не реже 1 с — его зажим); `MinTime` 1 с, `PermitWithoutStream` | смысл тот же: мёртвый пир снимается через Time+Timeout; оркестратор (10 с) GOAWAY не получает — доказано тестом |
| `0.0.0.0` | IPv4 | явно `tcp4` для IPv4-адреса (Go по `tcp` слушал бы и IPv6) | паритет |
| неверный PEM | ошибка на `bindAsync` | ошибка при загрузке сертификатов (`failed to load`) | исход тот же — выход 1 |
| `GetAgentInfo`: хеш | proto читался из cwd при старте; нет файла — пустой хеш | хеш считается из дескриптора, вшитого в бинарник | A R-15 |
| версия | `git describe` в cwd → `package.json` → `1.0.0` | сначала версия из `-ldflags`, потом та же цепочка | бинарник без `.git` рядом |
| `SelfUpdate` | git reset + npm ci + build + restart, без замка и таймаутов | бинарник релиза, SHA-256, проверка `--version`, атомарная подмена, `.prev`; повтор во время работы — `success:true` «already in progress», второе не запускается | §3 (решение владельца), A R-3, R-4, R-5; см. `update.md` |
| `GetManagedCertificate` | cert и key читались параллельно — при двух сбоях ошибка «кто первый» | сначала cert, потом key | детерминизм; текст ошибки в форме Node (`ENOENT: no such file or directory, open '<путь>'`) сохранён |
| остановка | SIGTERM — немедленная смерть | `GracefulStop` до 3 с, затем `Stop` | A §1.4 допускает |
| фоновые циклы | `setInterval`, тики накладываются | `lifecycle.Loop`: следующий тик — после окончания текущего | architecture §2 |
