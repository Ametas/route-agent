# Перевод агента на Go (ветка `alpha`)

Решение владельца 2026-11-06: агент переписывается на Go в отдельной ветке и вливается в `main`
одним PR, когда новый агент целиком повторяет старый. Пока перевод идёт, `main` живёт как раньше:
исправления агента на TypeScript делаются там и выкатываются обычным путём.

## Две ветки (2026-11-07)

- **`main` — stable.** Релизы semantic-release (`vX.Y.Z`); узлы обновляются отсюда по умолчанию.
- **`alpha` — nightly.** Бывшая `go-rewrite`: Go-агент. Каждый push в `alpha` после зелёных
  проверок пересобирает пре-релиз `nightly` (задание `nightly` в `go.yml`).

Узел переводит на nightly оркестратор — кнопка «Поставить Nightly», то есть SelfUpdate с
заголовком `x-agent-channel: nightly` ([`update.md`](update.md), [`cutover.md`](cutover.md) §A).

## Как устроена ветка

- **Go-код лежит рядом с TypeScript, а не вместо него**: модуль Go в корне (`go.mod`,
  `cmd/route-agent/`, `internal/…`), `src/` и `tests/` не трогаются до самого конца. Поэтому
  `main` вливается в ветку без конфликтов, и каждое исправление старого агента видно диффом
  `src/` — его надо повторить в Go.
- **Протокол — тот же `proto/agent.proto`**, байт в байт. Оркестратор при переходе не меняется:
  сверка договора (`protoContractVerifier`) считает тот же хеш.
- **Коммит перехода** (слияние `alpha` в `main`) убирает `src/`, `tests/` и остальное от Node и переключает
  `install.sh` и CI на Go. `package.json` и lock при этом остаются: их `npm run build` запускает
  мост перехода. Точный состав коммита и порядок раскатки — [`cutover.md`](cutover.md).

## Исправление в `main`, пока идёт перевод

1. Исправление делается и выкатывается в `main`, как обычно.
2. `main` вливается в `alpha` (`git merge origin/main`, без rebase: ветку смотрят несколько человек).
   В `package.json` у `alpha` остаётся свой `build` (`bridge-to-go.sh --channel nightly`).
3. Дифф `src/` из этого слияния повторяется в Go и в его тестах; строка в журнале ниже.

## Как ведётся работа

1. **Спецификация** (`spec/`): что делает каждый метод сегодня — входы, файлы и команды с точными
   аргументами, ответы, строки, на которые смотрит оркестратор, откаты, таймеры, «почему» из
   комментариев и тестов. Источник правды при переносе — она и тесты TypeScript.
2. **Архитектура** (`architecture.md`) — согласуется с владельцем до кода.
3. **Перенос по группам** (A–F, как в `spec/`), у каждой группы — свои тесты на Go, повторяющие
   пункты «Parity checklist» её спецификации.
4. **Проверка на живом узле**: новый агент на тестовом узле, оркестратор гоняет все действия журнала.
5. **Выкатка по одному узлу**, старый агент остаётся для отката.
